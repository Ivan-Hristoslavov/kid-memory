# Пускане онлайн (Vercel)

## 1. Преди качване — задължително

- [ ] Попълни фирмените данни в `.env` (виждат се на правните страници и в подвала):
      `NEXT_PUBLIC_COMPANY_NAME`, `NEXT_PUBLIC_COMPANY_EIK`,
      `NEXT_PUBLIC_COMPANY_ADDRESS`, `NEXT_PUBLIC_COMPANY_EMAIL`,
      `NEXT_PUBLIC_COMPANY_PHONE`
- [ ] `TEST_MODE="false"` — иначе админът е **отворен без парола**
- [ ] Силна `ADMIN_PASSWORD` (вече е генерирана)
- [ ] Ротирай ключовете, споделяни в чат: Supabase `service_role`, DB парола,
      `OPENAI_API_KEY`, `GEMINI_API_KEY`
- [ ] `OWNER_EMAIL` — там идва известието за нова поръчка
- [ ] `RESEND_API_KEY` + верифициран домейн за `EMAIL_FROM`

## 2. Качване

```bash
npm i -g vercel
vercel            # свързва проекта
vercel --prod     # пуска онлайн
```

При първото качване Vercel пита за настройки — приеми предложените
(Next.js се разпознава автоматично).

## 3. Environment variables във Vercel

Project → Settings → Environment Variables. Добави **всичко от `.env`**, като
смениш:

| Променлива | Стойност в продукция |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | `https://твоя-домейн.bg` |
| `TEST_MODE` | `false` |
| `STORAGE_DRIVER` | `supabase` |

Не качвай `.env` във хранилището — той е в `.gitignore`.

## 4. Домейн

Project → Settings → Domains → добави домейна и насочи DNS към Vercel.
След това обнови `NEXT_PUBLIC_SITE_URL` и пусни ново качване.

## 5. Автоматични задачи (cron)

`vercel.json` съдържа два крона, и двата искат `CRON_SECRET` във Vercel:

- `/api/cron/cleanup-photos` — дневно в 03:00, трие снимките след 90 дни
- `/api/cron/recover-abandoned` — на всеки час, изпраща имейл за незавършена поръчка

## 5б. Плащане с карта (по избор)

Магазинът работи без това — наложеният платеж е включен винаги. Картовото
плащане се пуска, когато има регистрирана фирма и Stripe акаунт, и носи две
неща: платената поръчка не може да бъде отказана на вратата, и дигиталният
файл (19.90 → 12.90 €, без печат и куриер) се връща в продажба.

1. Stripe → Developers → API keys → копирай **Secret key**.
2. Stripe → Developers → Webhooks → **Add endpoint**:
   - URL: `https://<домейн>/api/webhooks/stripe`
   - Събития: `checkout.session.completed`,
     `checkout.session.async_payment_succeeded`,
     `checkout.session.async_payment_failed`, `checkout.session.expired`
   - копирай **Signing secret**.
3. Във Vercel добави и трите:
   - `NEXT_PUBLIC_STRIPE_ENABLED` = `true`
   - `STRIPE_SECRET_KEY` = секретният ключ
   - `STRIPE_WEBHOOK_SECRET` = signing secret-ът
4. Пусни ново качване — `NEXT_PUBLIC_*` се вгражда при build, не при стартиране.

⚠️ И трите заедно. Без `STRIPE_SECRET_KEY` картата не се показва изобщо (по
проект — по-добре една работеща опция, отколкото бутон, който гърми). Без
`STRIPE_WEBHOOK_SECRET` клиентът плаща, но поръчката **никога не се потвърждава**
— webhook-ът връща 400 и парите стоят в Stripe без поръчка зад тях.

Локален тест: `stripe listen --forward-to localhost:3000/api/webhooks/stripe`,
после карта `4242 4242 4242 4242`, произволна бъдеща дата и CVC.

## 6. Проверка след пускане

- [ ] `TEST_MODE` е **изтрит или false** — при `true` /admin се отваря без парола
- [ ] `/admin` иска парола
- [ ] Правните страници показват истинските фирмени данни
- [ ] Тестова поръчка → идва имейл до клиента **и** до `OWNER_EMAIL`
- [ ] Имейлът показва **крайната сума с доставката** и бутон „Потвърждавам поръчката"
- [ ] Бутонът води до `/potvurdi/<token>` и поръчката става потвърдена в админа
- [ ] `/proverka` намира поръчката по номер + телефон

Ако картовото плащане е включено, допълнително:

- [ ] На `/order` се показват двата начина на плащане
- [ ] Плащане с тестова карта → връща на `/success` с „Плащането е прието"
- [ ] Поръчката в админа е **платена** и влиза направо в „За печат" (без чакане
      на потвърждение от имейл)
- [ ] Прекъснато плащане → поръчката **не** е потвърдена и не е в никоя опашка
- [ ] Дигитална поръчка → идва имейл с линк за сваляне, и файлът се сваля от
      `/moite`
- [ ] Прегледът е с воден знак и не може да се свали
- [ ] Банерът за бисквитки се появява; аналитиката тръгва само след съгласие
- [ ] **Една реална тестова пратка с Еконт** — куриерът да събере точно сумата от
      имейла и **да не иска отделно пари за доставка** (виж `ECONT_SENDER_PAYMENT`)

## 7. Реклами и проследяване

- `NEXT_PUBLIC_GA_ID` — Google Analytics
- `NEXT_PUBLIC_META_PIXEL_ID` — Meta пиксел
- `META_CAPI_TOKEN` — **задължителен, ако ще пускаш реклами.** Без него
  конверсиите от хора, отказали бисквитки, не стигат до Meta и алгоритъмът
  оптимизира върху част от данните.

## 8. Куриери

- `ECONT_API_USER`, `ECONT_API_PASSWORD` — товарителници на Еконт
- `ECONT_SENDER_PAYMENT` (по подразбиране `credit`) — кой плаща куриерската
  услуга. Доставката вече е включена в наложения платеж, така че тя трябва да е
  за сметка на подателя. Сгреши ли се, клиентът плаща доставката два пъти.
- `SPEEDY_USERNAME`, `SPEEDY_PASSWORD` — товарителници на Спиди
